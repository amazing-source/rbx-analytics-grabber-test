Three limits on the cost figures

Revenue per message is an upper bound on displacement. It assumes every free message replaces a bought one. Only 1.1–1.3% of run-outs convert, so most messages go to players who would not have bought. The true figure sits between the two columns, nearer the floor.

LLM APIs bill per token, not per query. A per-query rate is a stand-in; the driver is prompt plus completion tokens per reply, and the skins change the persona text, which moves the prompt side without changing the message count. The invoice is the only exact source.

10.0M/day is a window average across 12 Aug – 8 Sep, not a post-update-only figure. Per-player consumption rose while DAU fell over that window, so the current daily number is close to it but not split out.

How this was built

One browser grab per universe on 09 September 2026, a 28-day pass followed by a trailing 3-day pass, because a long window drops the newest day. The corpus CSVs are then loaded into DuckDB and every figure on this page comes from a single view, panel, built with four filters:

tools/panel-duck.js · the filters between the corpus and every number here
FilterWhy
granularity = 'METRIC_GRANULARITY_ONE_DAY'One CSV holds minute, half-hour and daily rows under the same date. Without this a half-hour bucket overwrites the daily value.
series = 'Total' or 'Place=<id>'The headline series is the one with no breakdown. A Place filter still covers the whole game; an AcquisitionSource or Platform row is a slice and is excluded here.
status <> 'FILLED_ZERO'A synthesised zero standing in for a row the API omitted. Not a reading.
partial IS NOT TRUEAn interval that had not finished when it was captured.

Panel totals: 24,426 rows across 75 metrics and five universes, written to analysis/panel-duck/panel.parquet. Gates on the day: npm test 51/51, npm run audit-plan 180 templates / 0 failures, npm run verify 24 pass / 2 fail / 7 skip with both failures the documented held pair.

Two things this page deliberately does not do

It does not attribute any movement to the build, and it does not rank anything by severity. Both windows are shown so the reader can see the level before the publish as well as after it, and every metric is printed whether it moved or not.

One measurement caveat that does belong here: 08 September client FPS and memory are not usable on any game. The same ~78% drop appears on all five universes on that date while session length and crash rate stay flat, and the following day recovers. Those cells are excluded.
